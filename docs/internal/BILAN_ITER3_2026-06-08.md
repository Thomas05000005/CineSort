### Branche retenue : **ii.b PYDANTIC SILENCIEUX (dominante)**

**Preuve** : `cinesort/ui/api/facades/run_facade.py` L110-119 — adaptation defensive
du payload AVANT validation pydantic :

```python
if isinstance(settings, dict) and "library_path" in settings:
    request_payload = settings        # dict plat re-emballe tel quel
else:
    request_payload = {
        "library_path": (settings or {}).get("library_path", ""),
        "options": settings,
    }
_ = _validate_passive(StartPlanRequest, request_payload, endpoint="start_plan.request")
```

Le schema `cinesort/ui/api/schemas/run.py` L41-59 (`StartPlanRequest`) exige une cle
top-level `settings: PlanSettings`. Or `request_payload` construit ci-dessus est SOIT
le dict plat `{library_path: "..."}` (branche `if`), SOIT `{library_path, options}`
(branche `else`) — **AUCUN des deux ne contient la cle `settings`** -> validation
echoue systematiquement -> warning + fallback dict.

Le fallback retombe sur `self._api._start_plan_impl(settings)` avec le `settings`
original qui — selon le smoking gun pydantic — ne contient QUE `library_path`. Tout le
reste (`tmdb_enabled`, `tmdb_api_key`, `tmdb_cache_ttl_days`, ...) est absent du dict
recu. Dans `cinesort/ui/api/run_flow_support.py:_init_tmdb_client` L196-223 :
- L196 : `tmdb_enabled = to_bool(settings.get("tmdb_enabled"), True)` -> True (default)
- L198 : `api_key = (settings.get("tmdb_api_key") or "").strip()` -> "" (vide)
- L204 : `if tmdb_enabled and api_key:` -> False (api_key vide)
- L220 : `elif tmdb_enabled:` -> devrait logger WARN "TMDb active mais cle vide"

L'absence du log WARN attendu (point 3) reste a confirmer (rs.log -> logger Python).
La cause racine du non-enrichissement TMDb est neanmoins la **perte du contexte
settings cote caller REST**, masquee par le fallback silencieux pydantic.

Ce n'est PAS la branche **ii.a ROUTAGE** (aucun `if not enabled: return` n'a saute,
car la cle `tmdb_enabled` est absente du dict — pas explicitement False). Ce n'est
PAS la branche **ii.c MAPPING** (le path d'enrichissement n'est meme pas atteint,
le scan se termine en 0.2 s sans appel reseau).
