**Argumentaire** :

1. **Echelle architecturale differente** :

2. **Bounded context different** :
   - Le mot "settings" dans `PlanSettings` est polysemique avec le bounded context Settings (`SettingsFacade.get_settings/save_settings` qui lit/ecrit `%LOCALAPPDATA%/CineSort/settings.json` utf-8-sig). Ici, `PlanSettings` modelise le **dict d'options de scan** (library_path + ~50 cles legacy comme `tmdb_api_key`, `tmdb_enabled`) passe en kwarg a `start_plan(settings=...)`. C'est l'argument de la methode, pas la table de configuration utilisateur.

3. **Toggle et fallback different** :
   - Cote auth (racine facade) : toggle = `CINESORT_DISABLE_LOCAL_AUTH` (env var) ; fallback = bypass inconditionnel renvoyant `True` sans lire le token. C'est un **bypass securite**.
   - Cote Pydantic (cluster settings) : toggle = `CINESORT_PYDANTIC_STRICT` (env var) ; fallback = retourner le payload dict legacy. C'est un **bypass validation de schema**, non securitaire (le run continue avec les memes donnees brutes que pre-Pydantic).
   - Les deux env vars sont independantes, leurs domaines disjoints, leurs criteres d'evaluation disjoints (pas de partage de code path).

4. **Site d'appel different** :
   - L'auth est gatee par `_handle_post()` (rest_server.py L918) en amont du dispatcher, avant que le wrapper facade ne soit invoque.
   - Le `_validate_passive` est appele a l'INTERIEUR de `RunFacade.start_plan` (L133, L140), donc strictement APRES que `_check_auth()` a deja repondu OK. Si l'auth refuse en amont, le pattern Pydantic n'est jamais atteint.

5. **Impact des tests #2/#3/#4 sur ce cluster** : **NUL**. Aucun des 3 tests cibles (test_dashboard_infra/test_log_context/test_dashboard_shell) ne frappe `start_plan` ni n'instancie un `StartPlanRequest`/`PlanSettings`. Tous frappent `get_settings` (lecture facade Settings ou route legacy). Le `_validate_passive` de S1 n'est jamais execute pendant ces tests. Inversement, fixer le bypass loopback (positionner `CINESORT_DISABLE_LOCAL_AUTH=1` dans `setUpClass`) n'a aucun effet sur le pattern Pydantic silencieux : meme env var positionnee, un `start_plan` reel avec un `settings` mal-forme retombera toujours sur le fallback dict (flag strict = 0).
