## 1. Conception proxy (endpoint, whitelist tailles, anti-SSRF, cache disque, etage/couches) [OPERATIONNEL_DESIGN]

> Statut section 1 : conception FIGE, pret pour implementation section 2.
> Verdict : design valide les 7 garde-fous (anti-SSRF, anti-open-relay, cle TMDb scrubbe, cache disque, couches respectees, backward compat, ordre strict avant CSP).

### 1.1 Endpoint signature [FIGE]

`GET /api/poster?id=<tmdb_id>&size=<size>`

- Methode : **GET** (idempotent, cacheable HTTP standard, compatible `<img src>`).
- Pas `POST /api/<facade>/<methode>` : c'est une ressource binaire reconnaissable par l'utilitaire `<img>` du navigateur. Le dispatcher facade n'est pas adapte (body JSON, reponse JSON, auth Bearer ecrite en JS - le navigateur ne peut pas la mettre sur `<img src>`).
- Reuse du chemin auth deja en place : la route GET est servie sur la meme socket que `/api/health` et `/api/spec`, MEME bypass loopback applicable (`_check_auth` est appele depuis `_handle_get` si on ajoute le check sur la nouvelle route).
- Hors-scope iter12 : `GET /api/poster` est verrouille loopback (`bind_host == "127.0.0.1"`). Cas LAN (bypass desactive + client distant) deferre section 5.

### 1.2 Whitelist tailles (FIGE) [FIGE]

```python
_POSTER_SIZES_ALLOWED: frozenset[str] = frozenset({"w92", "w185", "w342", "w500"})
```

- Toute autre valeur (vide, `original`, `w999`, casse differente comme `W92`) -> `400 validation` immediat.
- Pas de comparaison `lower()` cote serveur : on attend la valeur exacte de la whitelist (le frontend doit envoyer en lowercase).
- Constante stockee dans `cinesort/infra/integrations/poster_proxy.py` (FIGE, pas exposee aux settings utilisateur).

### 1.3 Validation id (anti-SSRF) [FIGE]

```python
_TMDB_ID_REGEX = re.compile(r"^[1-9]\d{0,9}$")
```

- Doit etre un entier strictement positif (1 a 9_999_999_999), regex compile, validation stricte.
- `id` vide, `id=0`, `id=-1`, `id=abc`, `id=1.5`, `id=1e3` -> `400 validation` immediat.
- L'`id` est ensuite cast `int()`, jamais concatene en string libre dans une URL.
- **Aucun parametre `url`, `poster_path`, `path`, `image_url` accepte** : sinon vector SSRF (le client pourrait forcer le serveur a fetcher `http://internal-jenkins:8080/secret`). Toute query string supplementaire est ignoree silencieusement.

### 1.4 Resolution poster_path et construction URL TMDb (anti-open-relay) [FIGE]

URL TMDb construite **COTE SERVEUR** apres validation :

1. Validate `id` (regex) et `size` (whitelist) -> sinon 400.
2. Resoudre `poster_path` via le cache TMDb existant : `tmdb_client.get_movie_poster_path(id)` qui retourne `"/abc123.jpg"` ou `None`.
   - Si `None` : retourner `404` propre (le film TMDb existe mais n'a pas de poster, ou l'`id` n'existe pas du tout). La distinction n'est pas faite cote client (anti-enumeration).
3. Sanitize `poster_path` : doit matcher `^/[A-Za-z0-9_.-]+$` (no slash multiple, no `..`, no query string). Si KO -> `502` cache pollue (log WARNING).
4. Construire `url = f"https://image.tmdb.org/t/p/{size}{poster_path}"` (`size` et `poster_path` sont alors tous deux valides selon la whitelist + regex). **Aucune valeur libre du client n'apparait dans l'URL.**
5. Fetch via `requests` session (reutilise le pattern existant `make_session_with_retry`) avec `allow_redirects=False`, `timeout=10s`, `stream=True` (pour borner le payload memoire avant ecriture cache).
6. Verifier `Content-Length` (ou borner stream lecture) <= 5 MB. Au-dela -> 502 (anti-DoS).

### 1.5 Cache disque (cle, structure, sanitize) [FIGE]

**Path racine** : `<APP_DATA_DIR>/cache/posters/<size>/<id>.<ext>`

- `APP_DATA_DIR` resolu via `cinesort.infra.state.default_state_dir()` (deja en place : `%LOCALAPPDATA%/CineSort` sur Windows, `Path(".") / CineSort` sinon -> OS-agnostic gracieux).
- `<size>` : appartient a `_POSTER_SIZES_ALLOWED` (deja sanitize par validation).
- `<id>` : entier deja valide (regex).
- `<ext>` : deduite du `Content-Type` TMDb reponse (`image/jpeg -> jpg`, `image/png -> png`, `image/webp -> webp`). Si Content-Type inattendu -> 502 (anti-content-confusion).
- Mkdir `parents=True, exist_ok=True` au boot du module (lazy, idempotent).

**Anti path-traversal** :
- `size` valide par whitelist (aucun `..`, aucun `/`).
- `id` valide par regex (aucun caractere special).
- `ext` valide par whitelist `{jpg, png, webp}`.
- Le nom final est donc strictement `<int>.<jpg|png|webp>` dans un dossier `<size>/` connu. AUCUNE valeur libre du client n'apparait dans le path.
- Verification de defense en profondeur : `cache_file.resolve()` doit etre sous `cache_root.resolve()` (assertion en debug).

**Cache hit / miss workflow** :
1. Build `cache_file = cache_root / size / f"{id}.{ext_candidate}"` pour chaque ext de la whitelist `[jpg, png, webp]`, tester `exists()`.
2. Si trouve : servir directement (200, `Cache-Control: public, max-age=2592000` (30j), `ETag` = sha1(`<id>|<size>|<size_bytes>`)).
3. Si miss : fetch TMDb (voir 1.4), determiner `ext` depuis Content-Type, ecrire atomic (`.tmp` -> `os.replace`), servir.
4. Si TMDb 404 : ne **pas** ecrire de marker negatif sur disque (eviter empoisonnement cache si TMDb corrige plus tard). Reponse `404` ephemere.
5. Si TMDb 5xx / network error : si cache existe (meme ancien), servir le cache (fallback graceful). Sinon `502` (online error) ou `503` (offline + miss).

**TTL / LRU** : non implemente iter12 (hors-scope, defere). Le cache croit lineairement avec la bibliotheque. Estimation : 5000 films x 4 sizes x ~30 KB moyen = ~600 MB max -> tolerable sur disque local. Purge manuelle possible via flush dossier.

### 1.7 Cle TMDb (jamais loggee, jamais exposee) [FIGE]

- L'`api_key` TMDb est stockee dans `TmdbClient.api_key` (initialise par `app.py` au boot).
- L'URL fetched cote serveur (`https://image.tmdb.org/t/p/...`) **n'inclut PAS l'api_key** : les CDN d'images TMDb (`image.tmdb.org`) sont PUBLICS, aucune auth requise (cf doc TMDb officielle : "Images do not require authentication"). C'est crucial : on n'a pas a transmettre la cle pour fetcher les posters.
- Aucun header `Authorization` ne quitte le serveur vers `image.tmdb.org`.
- Aucun log ne contient la cle (scrubber `log_scrubber.py` deja en place avec 8 patterns secrets).
- Aucun message d'erreur renvoye au client ne contient la cle (les erreurs 4xx/5xx sont des reponses generiques `{"ok": false, "message": "..."}`).
- Cote client : `<img src="/api/poster?id=123&size=w185">` -- aucun token, aucun secret, aucun parametre sensible.

### 1.8 Headers de reponse [FIGE]

| Statut | Headers | Body |
|--------|---------|------|
| 200 | `Content-Type: image/jpeg|png|webp`, `Content-Length: N`, `Cache-Control: public, max-age=2592000, immutable`, `ETag: "<sha1>"`, `X-Content-Type-Options: nosniff` | bytes image |
| 304 | `ETag: "<sha1>"`, `Cache-Control: public, max-age=2592000` | vide |
| 400 | `Content-Type: application/json` | `{"ok": false, "category": "validation", "message": "..."}` |
| 404 | `Content-Type: application/json` | `{"ok": false, "category": "resource", "message": "Poster not available"}` |
| 502 | `Content-Type: application/json` | `{"ok": false, "category": "runtime", "message": "Upstream error"}` |
| 503 | `Content-Type: application/json` | `{"ok": false, "category": "runtime", "message": "Cache miss offline"}` |

- ETag = `sha1(f"{id}|{size}|{file_size_bytes}")` (deterministe, change si TMDb pousse une nouvelle version).
- `Cache-Control: immutable` autorise le navigateur a garder la ressource sans revalidation pendant 30j (gain perf grosse biblio).

### 1.9 Codes d'erreur (categorisation) [FIGE]

| Code | Condition | Cas |
|------|-----------|-----|
| 200 | image servie | cache hit OU miss + fetch TMDb OK |
| 304 | If-None-Match matche ETag | revalidation conditionnelle |
| 400 | `id` invalide (vide, non-int, <= 0) | anti-SSRF |
| 400 | `size` hors whitelist | anti-SSRF |
| 404 | `get_movie_poster_path(id)` retourne None | film TMDb sans poster |
| 404 | TMDb retourne 404 sur l'image | image absente |
| 502 | TMDb 5xx OU CircuitOpen OU sanitize KO OU Content-Type inattendu OU body > 5 MB | erreur amont |
| 503 | Cache miss + reseau offline (DNS fail, ConnectionError) | offline, pas de fallback cache |

### 1.10 Anti-SSRF / Anti-open-relay (synthese) [FIGE]

- AUCUN parametre URL libre accepte (pas de `url=`, `path=`, `poster_path=`). Ces noms sont ignores silencieusement (pas leves en 400 pour eviter l'enumeration des parametres).
- `id` valide par regex `^[1-9]\d{0,9}$` -> impossible d'injecter `../`, `;`, `&`, etc.
- `size` valide par whitelist frozenset -> impossible d'injecter `..` ou autre.
- URL TMDb construite par f-string apres validation -> `f"https://image.tmdb.org/t/p/{size}{poster_path}"` ou tous les composants sont garantis sains.
- `allow_redirects=False` sur le `requests.get` cote serveur -> impossible que TMDb redirige vers un autre host (defense en profondeur, peu probable mais 0 cout).
- `stream=True` + `iter_content(chunk_size=8192)` avec limit 5 MB -> anti-DoS memoire.
- `cache_file.resolve().is_relative_to(cache_root.resolve())` -> assertion defense en profondeur path-traversal.

### 2.3 Construction URL TMDb cote serveur (anti-open-relay) [OPERATIONNEL]

Sequence stricte dans `fetch_and_cache` :
1. `poster_path = tmdb_client.get_movie_poster_path(tmdb_id)` (cache local, jamais valeur libre client).
2. Sanitize `poster_path` via `POSTER_PATH_REGEX = ^/[A-Za-z0-9_.-]+$` -> 502 si KO.
3. URL construite par f-string : `f"https://image.tmdb.org/t/p/{size}{poster_path}"` (size et poster_path tous deux valides).
4. Fetch via `session.get(url, allow_redirects=False, stream=True, timeout=10s)` -> impossible de rediriger ailleurs.
5. Borne 5 MB (`MAX_POSTER_BYTES`) avec iter_content(chunk_size=8192) -> anti-DoS memoire.
6. Content-Type filtre par whitelist (`image/jpeg`, `image/jpg`, `image/png`, `image/webp`) -> 502 si inattendu.

### 2.4 Cache disque sanitize + atomic write [OPERATIONNEL]

- Racine : `<state_dir>/cache/posters/<size>/<id>.<ext>` ou `<state_dir>` = `default_state_dir()` (= `%LOCALAPPDATA%/CineSort`).
- `<size>` ∈ whitelist FIGE (aucun caractere special possible).
- `<id>` = int deja valide par regex.
- `<ext>` ∈ `{jpg, png, webp}` (whitelist dans `POSTER_EXT_BY_CONTENT_TYPE`).
- Defense en profondeur : `_is_under_root(cache_file, cache_root)` verifie que `cache_file.resolve()` est `relative_to(cache_root.resolve())` avant chaque lecture/ecriture. Toute discrepance -> 502 + log error.
- Ecriture atomique : `_atomic_write` ecrit dans `<id>.<ext>.tmp` -> `os.fsync` -> `os.replace`. En cas d'echec, `.tmp` est unlinked best-effort. Pas de fichier partiel possible.

### 2.5 Cle TMDb : scrubbing et zero exposition [OPERATIONNEL]

- L'URL `https://image.tmdb.org/t/p/<size><poster_path>` ne contient AUCUN api_key (CDN public).
- `session.headers` n'embarque pas d'`Authorization` (User-Agent uniquement : `"CineSort/7.6 PosterProxy"`).

export function posterProxyUrl(tmdbId, size) {
  const allowed = new Set(["w92", "w185", "w342", "w500"]);
