### 1.a Perimetre schema PlanSettings (run.py L15-38, StartPlanRequest L41-59)

Le schema declare seulement 2 champs typed :
- `library_path: str` (obligatoire, min_length=1)
- `options: Optional[Dict[str, Any]]`

`model_config = ConfigDict(extra="allow")` => Pydantic ACCEPTE silencieusement TOUTES les autres cles legacy (~50 cles `tmdb_*`, `omdb_*`, `naming_*`, `perceptual_*`, ...) sans typer ni valider. C'est la facade `run_facade.start_plan` (L130-141) qui re-wrappe `{settings: {...}}` puis appelle `_validate_passive(StartPlanRequest, ...)` (passif, log ERROR + fallback).

Implication centrale : un toggle UI absent du dict d'origine cote caller REST sera reconstitue via `_hydrate_settings_from_store` (run_flow_support L614-647 : MERGE persisted then OVERRIDE par caller). Le drop/no-op se produit AVAL, soit dans `_init_tmdb_client` / OMDb branch / `build_cfg_from_settings` qui ignorent silencieusement les cles non lues.

### 2.b Classification BUG vs DESIGN DECISION

**`windows_safe` (toggle UI -> Parametres -> Renommage -> Regles)** :
- L'UI promet "Noms surs Windows (echappe < > : \" / \\ | ? *)".
- Le backend applique la sanitization NTFS de maniere INCONDITIONNELLE pour proteger l'OS (creer un fichier `foo:bar.mkv` sur NTFS = OSError obscur). Sur Windows c'est OBLIGATOIRE pour ne pas casser le rename.
- Le code est verrouille par 14+ sites externes referencant `_norm_win_path` (commentaire path_utils.py L86) et par `_RESERVED_DOS_NAMES` (CON/NUL/COM1-9/LPT1-9). Le fait que `windows_safe(name: str) -> str` n'expose aucun parametre est volontaire.
- **VERDICT : DESIGN DECISION (sanitization NTFS obligatoire), pas un drop silencieux**. Le toggle UI est une fausse promesse cote PRODUIT, mais STOP_FORK cote backend : on ne doit PAS introduire un fix qui permettrait de creer des noms invalides NTFS sur Windows. Le reglage devrait etre RETIRE de l'UI ou repositionne ("style de presentation" - separator entre tokens uniquement, jamais "echappe les caracteres NTFS"). C'est un sujet UI/UX et non un fix backend.

**`lowercase_extensions` (toggle UI -> Parametres -> Renommage -> Regles)** :
- L'UI promet ".mkv vs .MKV" — toggle qui force l'extension en minuscule.
- Le backend ne consomme JAMAIS cette cle. Le rename utilise `Path.suffix` qui preserve la casse source (ex: si fichier `Movie.MKV` -> rename garde `.MKV`).
- VRAI BUG d'avalage silencieux : reglage UI sans aucun effet runtime.
- **Fix au bon etage** : il faudrait propager `lowercase_extensions` dans `core.Config` puis dans le rendu d'`apply_core` (lignes L1996, L2101 + tous les sites video.suffix). Touche 12+ sites apply + plan_support_replan. NON_REPARABLE_FORK dans le cadre 1-commit-1-sujet de cette ITER.

**`separator` (selecteur UI -> Parametres -> Renommage -> Regles)** :
- L'UI propose 4 options : `.` `_` `-` `espace` pour le separateur entre tokens du template.
- Le backend stocke la valeur mais le moteur de template `naming.format_movie_folder` n'utilise PAS cette cle pour transformer le rendu (le template `{title} ({year})` ne sait pas comment substituer son espace).
- VRAI BUG d'avalage silencieux : selecteur UI sans aucun effet runtime.
- **Fix au bon etage** : il faudrait propager `separator` dans `core.Config` puis modifier `format_movie_folder` (domain/naming.py) pour post-traiter le resultat (replace ` ` par sep choisi sauf dans le titre tokenise). Risque eleve de regression sur naming_movie_template custom (utilisateurs avec template `{title}_{year}` deja en place verraient un double traitement). NON_REPARABLE_FORK dans le cadre 1-commit-1-sujet.
