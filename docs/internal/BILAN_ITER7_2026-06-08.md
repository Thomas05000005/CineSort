### 1.d Constats critiques [FIGE]

1. **`lowercase_extensions` est techniquement reparable** sans casser la backward compat des templates custom : c'est une normalisation post-rename sur `video.suffix.lower()`. La sortie d'un template `"{title} ({year})"` ne contient pas d'extension — le `.mkv` vient du `video.suffix` colle apres `format_movie_folder`. **Mais le pipeline actuel ne renomme JAMAIS le fichier video dans apply_single** (seul le dossier). Le fix se limite donc a `apply_collection_item` (`dst_video = sub_dir / video.name` L1928) et `apply_tv_episode` (L1996/L1998).

2. **`separator` est INTRINSEQUEMENT en STOP_FORK** : tout post-traitement du resultat de `format_movie_folder` casse les templates utilisateur deja en place. Sans un nouveau parametre `{sep}` dans le contexte template (deja propose en MEMOIRE refactor 2026-05-17 ?) ou un changement de signature `format_movie_folder(template, ctx, separator=...)` qui ne s'applique qu'aux espaces hors `{title}`, on ne peut pas le repare. **Confirme NON_REPARABLE_FORK** comme statue ITER6.

3. **Source unique fiable** : `_save_section_naming` lit avec coerce + defaut (cf code L1608-1612). Donc cote save tout est propre. C'est la lecture qui manque integralement.

4. **Pas de champ `Config`** : `core.Config.normalized()` (`domain/core.py:269-300`) ne propage ni `lowercase_extensions` ni `separator`. Aucun appelant non plus dans `apply_support.py:1340-1367` (la copie multi-root). Toute reparation passe forcement par :
   - (i) ajout de champs `Config.lowercase_extensions: bool = True` + `Config.separator: str = " "`
   - (ii) modification `build_cfg_from_settings` `settings_support.py:1045-1066` pour lire et passer ces champs
   - (iii) modification `Config.normalized()` pour les propager
   - (iv) modification call sites apply_core (L1928 + L1996 + L1998 pour `lowercase_extensions` ; pas faisable pour `separator` sans casser custom).

## 4. Fix separator [OPERATIONNEL]

### 4.a Strategie d'approvisionnement (opt-in via {sep})

Le constat ITER6/ITER7 section 1.d demeure : **tout post-traitement du resultat de `format_movie_folder` casserait les templates utilisateur custom existants** (ex `"{title} ({year})"` deviendrait `"{title}_({year})_"` avec `separator=_`). MEMOIRE `FORK SEMANTIQUE CUSTOM TEMPLATE = STOP REMONTER` formellement preservee.

La seule strategie compatible avec la consigne "INTERDIT: changer sortie template custom" est l'**approvisionnement opt-in via variable de template `{sep}`** :

1. **Domain** (`cinesort/domain/core.py`) : nouveau champ `separator: str = " "` sur `Config` + propagation dans `normalized()` avec coerce-and-default identique a `_save_section_naming` (in `{".", " ", "_", "-"}` sinon `" "`). Default `" "` aligne avec le sentinel du selecteur UI et le rendu historique du template `"{title} ({year})"`.

2. **Domain naming** (`cinesort/domain/naming.py`) :
   - `build_naming_context(*, separator: Optional[str] = None)` accepte le selecteur UI ; absent ou invalide -> `" "`.
   - Ajoute `ctx["sep"] = sep_value` au contexte rendu.
   - Ajoute `"sep"` dans `_KNOWN_VARS` (validateur de template) et `PREVIEW_MOCK_CONTEXT` (preview UI).
   - **Aucune modification de `format_movie_folder` ni `format_tv_series_folder` ni `_apply_template`** : la substitution se fait via `_VAR_RE.sub` deja en place ; les templates existants qui ne contiennent pas `{sep}` voient leur rendu strictement inchange.

3. **UI -> Domain** (`cinesort/ui/api/settings_support.py:build_cfg_from_settings`) : ajout d'un kwarg `separator=...` avec coerce-and-default identique. Resiste aux `settings.json` edites a la main avec valeur invalide.

4. **App** (`cinesort/app/apply_core.py`) : les 3 sites `build_naming_context(...)` (`apply_single` L1699-1707, `apply_collection_item` L1910-1916, `apply_tv_episode` L2010-2018) recoivent `separator=getattr(cfg, "separator", " ")`. Aucun nouvel import, aucune nouvelle dependance Domain<->App.

5. **App multi-root** (`cinesort/ui/api/apply_support.py:_execute_apply`) : propagation `separator=getattr(cfg, "separator", " ")` dans la recopie `cfg_for_root = core.Config(...)`. **Lecon ITER7 G.e re-appliquee** : sans cette ligne, le default `" "` ecraserait la valeur utilisateur sur les apply multi-root (meme cause racine secondaire que `lowercase_extensions` avant le fix complementaire).

Verification import-linter post-modif : **3 kept / 0 broken** (cf section 4.d).

### 4.b Garanties STOP_FORK CUSTOM TEMPLATE [FIGE]

Le fix ne touche STRICTEMENT JAMAIS la sortie d'un template existant :

1. **`_apply_template` (`naming.py:337-359`) inchange** : meme regex `_VAR_RE`, meme `_CLEANUP_PATTERNS`, meme `windows_safe`. La substitution `{sep}` -> valeur n'a lieu que si le template contient litteralement `{sep}`.

2. **`format_movie_folder` / `format_tv_series_folder` inchanges** : meme signature `(template, context)`, meme appel `_apply_template`. Aucune post-modification du resultat.

3. **Templates presets `default` / `plex` / `jellyfin` / `quality` / `custom`** (`naming.py:119-150`) ne contiennent PAS `{sep}`. Leur rendu est invariant entre `separator=" "`, `separator="_"`, `separator="."`, `separator="-"`.
