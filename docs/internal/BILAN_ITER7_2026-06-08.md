**Sites manquants pour `lowercase_extensions`** : Il existe AUSSI des renames de fichier film hors TV — `apply_collection_item` ligne 1928 fait `dst_video = sub_dir / video.name` (donc `video.name` complet, casse source preservee) et `apply_single` ne renomme pas le fichier video lui-meme (seulement le dossier parent). **Le fix `lowercase_extensions` doit cibler L1928 (`dst_video`) + L1996/L1998 (`video.suffix` TV) + tous les renames qui preservent `video.name`/`video.suffix`** — pas juste les 2 sites TV.

**Sites manquants pour `separator`** : Les 3 sites format (L1676, L1879, L1993) sont les seuls qui appliquent le template. Mais le risque est que `naming_movie_template` utilisateur EST DEJA `"{title} ({year})"` ou variante — si on post-traite avec `separator=_`, on transforme `Inception (2010)` -> `Inception_(2010)_` (ou pire). **C'est le STOP_FORK signale dans MEMOIRES** : "FORK SEMANTIQUE CUSTOM TEMPLATE = STOP REMONTER si separator/lowercase modifie sortie template custom existant".

### 1.d Constats critiques [FIGE]

1. **`lowercase_extensions` est techniquement reparable** sans casser la backward compat des templates custom : c'est une normalisation post-rename sur `video.suffix.lower()`. La sortie d'un template `"{title} ({year})"` ne contient pas d'extension — le `.mkv` vient du `video.suffix` colle apres `format_movie_folder`. **Mais le pipeline actuel ne renomme JAMAIS le fichier video dans apply_single** (seul le dossier). Le fix se limite donc a `apply_collection_item` (`dst_video = sub_dir / video.name` L1928) et `apply_tv_episode` (L1996/L1998).

2. **`separator` est INTRINSEQUEMENT en STOP_FORK** : tout post-traitement du resultat de `format_movie_folder` casse les templates utilisateur deja en place. Sans un nouveau parametre `{sep}` dans le contexte template (deja propose en MEMOIRE refactor 2026-05-17 ?) ou un changement de signature `format_movie_folder(template, ctx, separator=...)` qui ne s'applique qu'aux espaces hors `{title}`, on ne peut pas le repare. **Confirme NON_REPARABLE_FORK** comme statue ITER6.

3. **Source unique fiable** : `_save_section_naming` lit avec coerce + defaut (cf code L1608-1612). Donc cote save tout est propre. C'est la lecture qui manque integralement.

4. **Pas de champ `Config`** : `core.Config.normalized()` (`domain/core.py:269-300`) ne propage ni `lowercase_extensions` ni `separator`. Aucun appelant non plus dans `apply_support.py:1340-1367` (la copie multi-root). Toute reparation passe forcement par :
   - (i) ajout de champs `Config.lowercase_extensions: bool = True` + `Config.separator: str = " "`
   - (ii) modification `build_cfg_from_settings` `settings_support.py:1045-1066` pour lire et passer ces champs
   - (iii) modification `Config.normalized()` pour les propager
   - (iv) modification call sites apply_core (L1928 + L1996 + L1998 pour `lowercase_extensions` ; pas faisable pour `separator` sans casser custom).
