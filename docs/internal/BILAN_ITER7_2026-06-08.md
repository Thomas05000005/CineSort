### 1.d Constats critiques [FIGE]

1. **`lowercase_extensions` est techniquement reparable** sans casser la backward compat des templates custom : c'est une normalisation post-rename sur `video.suffix.lower()`. La sortie d'un template `"{title} ({year})"` ne contient pas d'extension — le `.mkv` vient du `video.suffix` colle apres `format_movie_folder`. **Mais le pipeline actuel ne renomme JAMAIS le fichier video dans apply_single** (seul le dossier). Le fix se limite donc a `apply_collection_item` (`dst_video = sub_dir / video.name` L1928) et `apply_tv_episode` (L1996/L1998).

2. **`separator` est INTRINSEQUEMENT en STOP_FORK** : tout post-traitement du resultat de `format_movie_folder` casse les templates utilisateur deja en place. Sans un nouveau parametre `{sep}` dans le contexte template (deja propose en MEMOIRE refactor 2026-05-17 ?) ou un changement de signature `format_movie_folder(template, ctx, separator=...)` qui ne s'applique qu'aux espaces hors `{title}`, on ne peut pas le repare. **Confirme NON_REPARABLE_FORK** comme statue ITER6.

3. **Source unique fiable** : `_save_section_naming` lit avec coerce + defaut (cf code L1608-1612). Donc cote save tout est propre. C'est la lecture qui manque integralement.

4. **Pas de champ `Config`** : `core.Config.normalized()` (`domain/core.py:269-300`) ne propage ni `lowercase_extensions` ni `separator`. Aucun appelant non plus dans `apply_support.py:1340-1367` (la copie multi-root). Toute reparation passe forcement par :
   - (i) ajout de champs `Config.lowercase_extensions: bool = True` + `Config.separator: str = " "`
   - (ii) modification `build_cfg_from_settings` `settings_support.py:1045-1066` pour lire et passer ces champs
   - (iii) modification `Config.normalized()` pour les propager
   - (iv) modification call sites apply_core (L1928 + L1996 + L1998 pour `lowercase_extensions` ; pas faisable pour `separator` sans casser custom).

## 3. Fix lowercase_extensions [OPERATIONNEL]

### 3.a Strategie d'approvisionnement (modele 9c806129)

Drop silencieux a trois etages (section 1 + 2 confirme) : la cle UI est sauvegardee
par `_save_section_naming` (`cinesort/ui/api/settings_support.py:1608-1609`) mais
`build_cfg_from_settings` (`settings_support.py:1045-1066`) instancie `core.Config`
sans la lire, et `core.Config` (`cinesort/domain/core.py:208-300`) n'expose AUCUN
champ correspondant. Resultat pipeline : `apply_core.py` utilise `video.suffix`
et `video.name` qui preservent la casse FS source (`.MKV` reste `.MKV`).

Approvisionnement RESPECTANT les couches (regle import-linter `domain_pure`) :

1. **Domain** (`cinesort/domain/core.py`) : nouveau champ
   `lowercase_extensions: bool = True` sur `Config` + propagation dans `normalized()`.
   Le default `True` aligne le contrat Domain sur la valeur par defaut de
   `_save_section_naming` (`to_bool(payload.get("lowercase_extensions"), True)`),
   ce qui evite toute regression silencieuse pour les configs anciennes ou
   editees a la main qui n'ont pas la cle.

2. **UI -> Domain** (`cinesort/ui/api/settings_support.py:build_cfg_from_settings`) :
   ajout d'un argument `lowercase_extensions=to_bool(settings.get("lowercase_extensions"), True)`
   a la construction `core.Config(...)`. Meme defaut que Domain pour la coherence.

3. **App** (`cinesort/app/apply_core.py`) : deux helpers prives places dans la couche
   App (legitime puisqu'ils consomment `Config` Domain pour orchestrer un detail
   de placement FS) :
   - `_video_ext(cfg, video) -> str` : retourne `video.suffix` ajuste selon
     `cfg.lowercase_extensions` (True -> `.lower()`, False -> preservation).
   - `_video_name_with_ext_case(cfg, video) -> str` : retourne `f"{video.stem}{_video_ext(cfg, video)}"`,
     pour les call sites qui composent le nom final cible a partir du nom source
     (single de collection, quarantaine).

   Aucun nouveau import inverse : `apply_core` est deja autorise a consommer
   `Config` (`from cinesort.domain.core import ...` deja en place). Le helper
   ne fuit pas vers Domain (cohabite avec les autres helpers prives `_name_eq_fs`,
   `_fs_equivalent`).

Verification import-linter post-modif : **3 kept / 0 broken** (cf. section 3.d).

### 3.c Decisions architecturales

- **Default True coherent** : Domain et UI partagent le meme default `True`. Pas de
  fork de comportement entre "champ absent en settings.json" et "champ explicite a
  True". Choix conservateur : la majorite des bibliotheques cinema preferent les
  extensions en minuscule (convention Plex/Jellyfin).
- **Helper en App pas en Domain** : le helper a besoin du contrat `Path` standard
  (`.stem` + `.suffix`), mais c'est une orchestration FS (couche App) pas une regle
  metier (couche Domain). Le placer en Domain creerait du bruit la-bas. Place
  en `apply_core` au plus pres des call sites consommateurs.
- **Aucune touche template custom** : on n'a pas touche `domain/naming.py` ni
  `format_movie_folder`/`format_tv_series_folder`. La regle s'applique strictement
  sur l'extension `.ext` du fichier, jamais sur le contenu du template (stem,
  separateur, etc.). Garantie FORK SEMANTIQUE CUSTOM TEMPLATE preservee.
- **Backward compat absolue** : aucune migration SQL, aucun changement de schema
  de `settings.json`, aucune cassure de signature publique. `Config` reste un
  `@dataclass(frozen=True)` ; ajouter un champ avec default ne casse aucun
  appelant existant (`Config(root=...)` continue de compiler).
- **windows_safe NON TOUCHE** : conformement a la consigne, on ne propage PAS
  `windows_safe` dans Domain dans ce commit. Sujet separe en attente de decision
  humaine.
- **ii.b bruyant preserve** : aucune logique de validation/echec n'a ete touchee.
