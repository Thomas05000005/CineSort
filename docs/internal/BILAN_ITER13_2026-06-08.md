### 3.b RETRY_BACKOFF — Retry exponentiel sur echec transitoire [OPERATIONNEL]

**Statut** : OPERATIONNEL (2026-06-10, branche `loop/correction-2026-06`).
**Perimetre** : RETRY_BACKOFF UNIQUEMENT — TIMEOUT_ADAPTATIF (3.a),
CIRCUIT_BREAKER (3.c), CACHE_PROBE (3.d) et POLLING_UI_BACKOFF (3.e)
traites par d'autres sous-agents en parallele.

#### Mecanisme implemente

Module nouveau : `cinesort/infra/probe/_retry_backoff.py` (~148 LOC).

Helper public `retry_with_backoff(fn, *, label, max_retries, base_delay_s,
max_delay_s, sleep_fn)` qui :

1. Execute `fn()` une 1ere fois.
2. Sur echec considere TRANSITOIRE (`_is_transient`), attend
   `base_delay_s * 2^attempt` cape a `max_delay_s`, puis re-essaie.
3. Borne `max_retries` (defaut **3**, override env `CINESORT_PROBE_RETRY_MAX`,
   clamp [0, 10]).
4. Log VISIBLE de chaque tentative — exigence ITER13 :
   `ffprobe retry attempt N/M apres TimeoutExpired, backoff X.Xs`.
5. Re-leve la derniere exception telle quelle apres epuisement.

Defaults : **1s / 2s / 4s / 8s plafond** (4 tentatives au total).

#### Perimetre transient (_is_transient)

Retry uniquement sur :
- `subprocess.TimeoutExpired` (NAS lent, gros 4K HEVC, contention I/O).
- `BrokenPipeError` (pipe ferme abruptement).
- `ConnectionError` Python builtin (couvre ConnectionReset / Aborted / Refused).
- `OSError` avec errno reseau : `EAGAIN`, `ETIMEDOUT`, `EHOSTUNREACH`,
  `ENETUNREACH`, `ENETDOWN`, `ECONNRESET`, `ECONNABORTED`, `EPIPE`.
- `OSError.winerror` ∈ {53, 64, 67, **121 (ERROR_SEM_TIMEOUT = NAS lent/down)**,
  1231}.

**Pas de retry** sur :
- `FileNotFoundError` (errno ENOENT) — tool absent, deterministe.
- `PermissionError` (EACCES) — droits, deterministe.
- `ValueError`, `TypeError`, `KeyError`, `json.JSONDecodeError` — applicatif.
- `KeyboardInterrupt`, `SystemExit`, `GeneratorExit` — arret administre du
  processus, doivent remonter immediatement.

### 3.c CIRCUIT_BREAKER — Source UNC degraded sur N echecs [OPERATIONNEL]

**Statut** : OPERATIONNEL (smoketest local OK 2026-06-10).
**Branche** : `loop/correction-2026-06`.
**Acquis preserves** : identification DECOUPLEE (iter4 racine C) — le breaker
n'influe QUE sur le probe, pas sur TMDb / NFO / filename. Backward compat
ABSOLUE — `source_breaker` est optionnel (defaut singleton process), ProbeService
sans param fonctionne comme avant.

#### Probleme cible
Sans circuit breaker par source, un partage UNC injoignable fait payer 30s de
timeout PAR FICHIER. Sur 5000 films d'une biblio reseau qui tombe, ~41h de hang
inutile avant que l'utilisateur ne voie le probleme.

Le `cinesort/infra/_circuit_breaker.py` existant cible les clients HTTP (TMDb /
Jellyfin / Plex / Radarr) avec granularite globale par client : ne convient pas
ici car on a besoin d'isoler PAR SOURCE UNC (\\nas\films vs \\autre\share vs
disque local C:\ qui doivent etre independants).

#### Solution
Module dedie `cinesort/infra/probe/_source_circuit_breaker.py` :

- `extract_network_source(path)` : retourne `\\host\share` (lowercase) ou
  `None` pour paths locaux. Les paths locaux ne sont JAMAIS surveilles.
- `SourceCircuitBreaker(failure_threshold=5, recovery_timeout=300)` defaults.
- Etats par source : CLOSED (defaut) -> DEGRADED apres N echecs consecutifs ->
  CLOSED auto apres timeout. Pas d'etat half-open (KISS).
- API : `check_or_raise(path)`, `record_failure(path)` (retourne `just_degraded`),
  `record_success(path)`, `is_degraded(path)`, `snapshot()`.
- Thread-safe : tous les acces `_states` sous lock (cf parallel probe via
  ThreadPoolExecutor).
- Singleton process-wide via `get_default_breaker()` (lazy init).
- Configurable via env `CINESORT_PROBE_BREAKER_THRESHOLD` /
  `CINESORT_PROBE_BREAKER_RECOVERY_S` ou ctor (tests).

#### Branchement dans `ProbeService.probe_file`
1. Constructeur accepte `source_breaker: Optional[SourceCircuitBreaker]`
   (defaut singleton).
2. Avant le subprocess (apres cache lookup, avant `_get_tools_cached`) :
   `self._source_breaker.check_or_raise(media_path)`. Si `SourceDegradedError`,
   retourne `_degraded_source_payload(...)` (helper extrait).
3. Apres normalize, si backend != "none" et `tool_unavailable=False` :
   - `raw_mediainfo is not None or raw_ffprobe is not None` -> `record_success`
   - sinon -> `record_failure`. Si bascule DEGRADED -> log WARNING visible.

#### Degradation visible JAMAIS silencieuse
Le payload `_degraded_source_payload` retourne :
```python
{
  "ok": True,
  "degraded_source": True,  # detection caller
  "source": "\\nas\films",
  "normalized": {...probe FAILED via normalize_probe avec message lisible...},
  "raw_json": {"mediainfo": None, "ffprobe": None},
  "sources": {"breaker_message": "Source reseau '...' degradee (...)"}
}
```

PAS score invente, PAS ligne disparue, PAS 0 trompeur. La couche
`quality_report_support` peut detecter `degraded_source` pour afficher
"indisponible" en clair.

### 3.d CACHE_PROBE — Cache disque JSON file-based [OPERATIONNEL]

**Statut** : OPERATIONNEL (smoketest local OK 2026-06-10).

**Acquis preserves** : identification DECOUPLEE du probe (iter4 racine C) — aucun

#### Mecanisme

Le cache DB `probe_cache` (table SQLite via `ProbeRepository`) reste autoritatif
mais une COUCHE SECONDAIRE cache disque JSON est ajoutee pour deux raisons :

1. **Resilience NAS / SMB** : si la DB SQLite subit `BrokenPipeError` / lock /
   contention WAL sur un partage reseau lent, le fallback disque permet quand
   meme un cache hit (le probe reste dispo).
2. **Independance multi-instance** : un fichier JSON par probe est lisible
   directement, partageable entre instances ou outils externes.

Le cache disque cohabite : lecture DB d'abord, fallback disque si miss / exception ;
ecriture des deux en best-effort. Backward-compat 100% : si tout marche en DB, le
comportement et la perf sont strictement identiques a avant.

| Fichier | Role |
|---|---|

  (defaut state_dir = `%LOCALAPPDATA%/CineSort`)
- Override : env `CINESORT_PROBE_CACHE_DIR`
