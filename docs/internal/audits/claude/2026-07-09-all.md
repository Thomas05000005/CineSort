## Detail des findings

### A1 — export_nfo_for_run : annee non numerique fait planter tout l'export (PR #725)

- `year = int(row.get("decision_year") or row.get("proposed_year") or 0)` (L258) **sans garde**.
  Une annee non numerique (`"N/A"`, `"?"`, annee mal parsee) leve `ValueError` ; la boucle
  `for row in rows` n'etant pas protegee, **tout l'export NFO plante** — aucun `.nfo` ecrit.
- Asymetrie revelatrice : `title` est deja enveloppe dans `str(...)`, pas `year`.
- **Fix** : `try/except (TypeError, ValueError)` -> `year = 0`. La row fautive est exportee avec
  `year=0` au lieu de faire echouer l'ensemble. Aucun changement de signature.
- **Test** : `test_non_numeric_year_does_not_crash` (2 rows, 1re avec `proposed_year="N/A"`,
  verifie `written == 2`).

### A2 — quality_simulator : tier_before legacy FR non normalise (PR #726)

- Dans `_recompute_in_memory`, `tier_before = rep.get("tier") or _tier_for(...)` (L257) lit le
  tier brut. Les rapports pre-migration peuvent contenir un ancien nom FR (Premium/Bon/Moyen/
  Faible/Mauvais), alors que `tier_after` emet toujours le nom canonique anglais.
- Consequence : `_count_tiers` cree des buckets fantomes et la matrice de shift produit des cles
  absurdes (`Premium>Platinum`). `improved`/`degraded`/`prem_delta`/`fail_delta` restent corrects
  (car `_TIER_ORDER` inclut les noms legacy) -> severite 2, pas de corruption.
- **Fix** : normaliser `tier_before` a la source via `normalize_tier_string`
  (`cinesort/domain/tiers_helpers.py`). Un seul point de verite.
- **Test** : `test_legacy_tier_before_normalized`.

### A3 — quarantine_ttl : orphelins .tmp du manifest comptes comme films (PR #727)

- `_save_ttl_manifest` ecrit un sibling `.cinesort_ttl_manifest.json.tmp.<pid>.<tid>` avant
  `os.replace`. Un crash entre write et replace laisse ce `.tmp.*` orphelin.
- `_iter_review_files` (L169) et la boucle top-level de la purge TTL (L424) n'excluaient **que le
  nom exact** du manifest -> l'orphelin etait compte comme film dans l'inventaire viewer et inscrit
  au manifest d'arrivee (telemetrie faussee).
- **Fix** : predicat `_is_ttl_manifest_file()` (manifest exact OU sibling `.tmp*`). Complement de
  la PR #654 (ecriture atomique). `purge_review_bucket_all` (mode tout-vider) non touche par design.
- **Test** : `test_orphan_manifest_tmp_not_counted_as_film` — suite 25 tests verte en local.

### A4 — custom_rules : score_multiplier negatif fait tomber en Reject silencieusement (Issue #723)

- `_act_score_mult` (L182-191) accepte un `factor` negatif : `score * (-1)` -> negatif -> `_clamp`
  ramene a 0 -> **Reject silencieux**, sans avertissement.
- Asymetrie : `_act_force_score` (L194-207) a ete explicitement durci pour exactement ce risque.
- **needs-review** : un facteur negatif est une entree utilisateur non idiomatique ; a valider avec
  le mainteneur avant PR (issue seule, pas de PR auto).

### A5 — duplicate_multi_signal : compteur telemetrie fuzzy_title sous-estime (Issue #724)

- L483-484 : le commentaire annonce compter aussi les ajouts a des groupes Phase A existants, mais
  `phase_counts[PHASE_FUZZY_TITLE] = len(groups_b)` ne compte que les **nouveaux** groupes.
- Impact limite au dict `phase_counts` (logge en `logger.info`). **Aucune corruption** -> severite 1.
- **Action** : issue seule (corriger le commentaire OU faire remonter le compte Pass 1).
