## Findings par categorie

### Categorie 1 — Bugs latents Python

1. **#655 (needs-review)** — `domain/core.py:1005` `build_candidates_from_tmdb`.
   `_TMDB_YEAR_FAR_THRESHOLD=3` rend la branche `elif year_delta>=6` inatteignable
   (le `elif year_delta>=3` la capture d'abord). Le palier de penalite modere
   (`_TMDB_SCORE_YEAR_FAR_PENALTY`, 0.08) n'est jamais applique. Pas de crash mais
   scoring TMDb sous-penalise les forts ecarts d'annee. **Pas de PR auto** : le
   fix (reordonner les paliers) change la semantique de scoring -> decision humaine.

### Categorie 2 — Sentinel value confusion

2. **PR #653** — `ui/api/dashboard_support.py:1519` `_compute_home_insights`.
   `if r.get("status") == "running"` ne matche jamais car la table `runs` stocke
   le statut en MAJUSCULES (`RUNNING`, cf `run.py:103`). L'insight "run en cours"
   de l'accueil est une feature morte silencieuse. Fix : normaliser en `.upper()`.

3. **#656 (needs-review)** — `domain/explain_score.py:127` `_weighted_delta_for_factor`.
   `int(weights.get("video", 60))` leve `TypeError` si une seule clef vaut `None`,
   et le `except` resette les TROIS poids a `60/30/10`, jetant les deux valeurs
   valides. Asymetrie avec la fonction soeur `_compute_category_contribution`
   (L79-84) qui coalesce par clef. **Pas de PR auto** : le fix naif `or 60` est
   FAUX (ressuscite un poids `0` legitime — anti-pattern documente L91-95). Fix
   correct = coalescing `is not None` par clef + decision sur la valeur par defaut.

### Categorie 9 — Concurrence

4. **#594 enrichie (CAS B)** — `ui/api/run_flow_support.py:623` +
   `ui/api/perceptual_support.py:1189,1287`. `threading.Thread` lance sans
   `copy_context()` / `set_run_id()` : les logs des threads de fond perdent la
   correlation `run_id` (ContextVar). Commente sur l'issue #594 existante plutot
   que d'ouvrir une issue concurrente.

5. **#628 enrichie (CAS B)** — `infra/omdb_client.py:320` `_cache_get` lit
   `self._cache` hors `self._lock` pendant que `_cache_set` le mute sous lock.
   Mitige par le GIL en CPython standard, mais data race reel sur builds
   free-threaded (PEP 703). Commente sur la PR #628 (qui touche deja ce fichier)
   au lieu d'une PR competitrice.

### Categorie 15 — Perte de donnees

6. **PR #654** — `app/quarantine_ttl.py:519` `purge_review_bucket_all`.
   La purge supprime le manifest TTL (`elif child.is_file()` sans exclusion),
   contrairement a `purge_review_bucket` (L424) qui le preserve. Perdre le manifest
   = perdre les dates d'entree -> TTL recalcule depuis `st_mtime` (regression du fix
   `7089cab` vague 1). Fix : exclure `child.name != _TTL_MANIFEST_NAME`. Verifie que
   `test_purge_all_wipes_everything_except_user_decided` (attend `deleted==4`) reste
   vert car ses `_write_file` omettent `root=` donc ne sement aucun manifest.
