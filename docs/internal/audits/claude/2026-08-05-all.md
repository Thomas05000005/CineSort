### A1 — le fil conducteur du run

`move_journal._rename_or_cross_device_copy` et
`cleanup._move_dir_without_destructive_fallback` portent une mesure explicite,
faite sur Windows 11 avec un simple `open()` sur un fichier interne :

| primitive | resultat sur un verrou d'UN fichier du dossier |
|---|---|
| `Path.rename` | `PermissionError` WinError 5, source **INTACTE**, destination **ABSENTE** |
| `shutil.move` | `PermissionError` WinError 32, destination peuplee **ET** source amputee |

Le garde `allow_copy_fallback=False` (PR #935) n'avait ete pose que sur **un**
site, `cleanup._move_dirs_to_bucket`. Les six autres deplacements de dossier
entier passaient encore par `shutil.move` nu :

- `apply_core.move_duplicate_losers_to_user_decided` (`MOVE_DIR`)
- `apply_core.move_marked_for_deletion_to_bucket` (`MOVE_DIR`)
- `apply_core.move_collection_folder` (`MOVE_DIR`)
- `apply_core.quarantine_row`, branche `single` (`QUARANTINE_DIR`)
- `apply_rollback._revert_one_op` (rollback atomique)
- `apply_support._execute_undo_ops`, 2 sites (undo)

Les deux derniers sont le **filet de secours** : le dedoublement survenait au
moment precis ou l'utilisateur demande a revenir en arriere. `apply_single`
renommait deja son dossier via `folder.rename` (`apply_core:2703`) : le correctif
aligne les six sites restants sur une regle qui existait deja dans le module.

## Par module

Seuls les modules porteurs d'un finding sont detailles. Les autres ont ete lus ou
instruits par recherche ciblee sans resultat retenu.

### `cinesort/app/apply_core.py` — severite 3 (BUG), cat. 2/31

`move_duplicate_losers_to_user_decided:1480`, `move_marked_for_deletion_to_bucket:1667`,
`move_collection_folder:1760`, `quarantine_row:3202`.
`atomic_move(..., op_type="MOVE_DIR"|"QUARANTINE_DIR")` sans `allow_copy_fallback=False`.
Toutes ces cibles sont sous `cfg.root`, donc `os.rename` suffit.
**Fix** : ajout du kwarg. Le comportement ne change **que** sur les erreurs
non-EXDEV ; un vrai franchissement de volume degrade toujours en copie. -> PR #939.

### `cinesort/app/apply_rollback.py` — severite 3 (BUG), cat. 31

`_revert_one_op:274` : `shutil.move(str(dst), str(src))` pour **tous** les op_type,
`MOVE_DIR` et `QUARANTINE_DIR` compris.
**Fix** : discrimination sur le suffixe de l'op_type ; les `*_FILE` gardent
`shutil.move` (pour un fichier isole, la copie fait justement aboutir un
deplacement que `rename` refuse sur un verrou en lecture partagee). -> PR #939.

### `cinesort/ui/api/apply_support.py` — severite 3 (BUG), cat. 31

`_execute_undo_ops`, sites `UNDO_QUARANTINE:654` et `UNDO_RESTORE:697`. Meme
defaut, sur le chemin de l'undo. Meme fix, avec le defaut `MOVE_FILE` de
`_resolve_hashed_target` pour une op sans type. -> PR #939.

### `cinesort/infra/log_context.py` — severite 2 (QUALITY), cat. 3/11

`RepeatedExceptionDedupFilter.filter:210`.

```python
if len(self._counts) > self._SWEEP_THRESHOLD:
    self._counts = {k: v for k, v in self._counts.items() if v}
```

`if v` ne peut **jamais** etre faux : seule la cle courante est elaguee, et elle
ressort non vide (soit elle a atteint `_max` et la fonction a deja rendu `False`,
soit on vient d'y pousser `now`). Le balayage recopie le dictionnaire a
l'identique ; la fuite qu'il annonce empecher reste entiere. Elle est reelle des
qu'un message est construit en f-string : une cle `msg[:80]` par film.
**Fix** : critere de **peremption** (`now - v[-1] < _WINDOW_S`) au lieu de la
vacuite, et fenetre de 60 s promue en constante de classe partagee avec
l'elagage. -> PR #940.

### `cinesort/app/quarantine_ttl.py` — severite 3 (BUG), cat. 4/31

`_purge_dir_recursive:472` et `purge_review_bucket:586`. Seul chemin de
suppression recursive **automatique** du depot (cron 24 h), et le seul sans garde
point d'analyse NTFS — `cleanup.py` et `apply_core.py` en ont un
(`_dir_utils.is_reparse_point`, x4 chacun). `child.is_dir()` accepte une jonction,
`rglob("*")` descend dedans, `item.unlink()` supprime la cible.
Une jonction arrive dans `_review` sans y etre creee : `quarantine_row` y deplace
le dossier du film **en entier**.
**Pas de PR** : trois options de correction s'opposent (refuser / supprimer le
lien seul / demander confirmation), c'est un arbitrage produit. -> issue #941.

### `cinesort/ui/api/facades/run_facade.py` — severite 2 (QUALITY), cat. 17/19

`undo_selected_rows:509` et `undo_by_row_preview:502` : exposees en facade,

### `cinesort/ui/api/run_flow_support.py`, `app/email_report.py`, `app/plugin_hooks.py` — severite 2, cat. 15

`run_flow_support:655` (`_bg_tmdb_enrich`), `email_report:257`, `plugin_hooks:91` :

### `cinesort/infra/state.py` — severite 2 (QUALITY), cat. 2

`clean_old_runs:448` : `shutil.move(str(review), str(dest))` deplace un `_review`
