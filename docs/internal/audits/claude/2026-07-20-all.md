## Findings retenus

### A1 — Intégrité M2TS/MTS : paquets 192o non supportés → **PR #784** (Closes #782) — HIGH

`cinesort/domain/integrity_check.py:131` — `_check_ts` ne vérifiait le sync byte `0x47` qu'aux
offsets `0/188/376` (paquets TS classiques 188o). Or `_EXT_TO_FORMAT` route `.m2ts`/`.mts` vers ce
check, et ces formats utilisent des paquets de **192o** avec un préfixe `TP_extra_header` de 4o → le
sync est à l'**offset 4**. Conséquence : tout M2TS/MTS légitime tombait en `header_mismatch` →
flag `integrity_header_invalid` (`plan_support_replan.py:498`), présent dans `_AUTO_INTEGRITY_WARNINGS`
(`run_read_support.py:17`) et `_SIDEBAR_CRITICAL_FLAGS` (`dashboard_support.py:2014`), donc
**auto-approbation bloquée + alerte critique à tort**.

**Fix** : constante `_TS_LAYOUTS = ((0, 188), (4, 192))`, boucle validant le premier layout dont les
3 sync bytes correspondent. Tests neufs `TsHeaderCheckTests` (TS classique, M2TS 192o, MTS 192o,
garbage → toujours mismatch).

### A2 — Cache updater écrit non-atomiquement → **PR #789** (Closes #787) — MEDIUM

`cinesort/app/updater.py:124` — `_write_cache` faisait `cache_path.write_text(...)` en place. Une
interruption laisse un JSON tronqué (dégradation gérée par `_read_cache` → re-fetch, pas de crash),
mais **diverge de la convention atomique du codebase** (`tmdb_client`, `poster_proxy`,
`quarantine_ttl` : `tmp` + `os.replace`). **Fix** : écriture dans `<name>.tmp.<pid>` puis
`os.replace`, nettoyage du tmp sur échec. Tests neufs `WriteCacheAtomicTests`.

### A6 — `to_optional_bool` avale `False`/`0` → **PR #786** (Closes #785) — MEDIUM

`cinesort/domain/conversions.py` — `to_optional_bool` faisait `str(value or "")`, transformant tout
falsy (`False`, `0`, `0.0`) en chaîne vide → `None`. Impossible de distinguer un bool/int falsy
légitime d'une absence. **Asymétrique** avec les 3 sœurs (`to_bool`, `to_optional_int`,
`to_optional_bitrate`) qui gardent le type en tête. Bug latent (les callers actuels passent des
strings) corrigé défensivement par les mêmes gardes de type que `to_bool`.

### A7 — Défaut `separator` incohérent (`.` vs espace) → **PR #788** (Closes #783) — MEDIUM

`cinesort/ui/api/settings_support.py` — `_save_section_naming` retombait sur `"."` quand le champ
`separator` était présent mais vide, alors que le défaut canonique est l'espace `" "`
(`core.py:259` ; `build_cfg_from_settings` : `str(settings.get("separator") or " ")`). Vider le champ
côté UI persistait donc `"."` au lieu de `" "`, **basculant silencieusement le séparateur de
nommage**. Fix : aligner le fallback du save sur `" "`.

### A3 — Jellyfin : match par préfixe de dossier → **issue #790** (sans PR) — HIGH

`cinesort/app/jellyfin_validation.py:81` — `build_sync_report` apparie film↔dossier par préfixe
(`startswith`) non ancré : un dossier `Alien` collisionne avec `Alien Resurrection`, `Aliens`, etc.
Le premier film matché capte toute une famille → rapports de sync erronés (faux « ghosts »).
**Pas de PR** : le fix correct (match exact / normalisation / ancrage sur séparateur de chemin)
est un choix produit, hors périmètre « fix évident ».

### A4 — OMDb : sentinelle `0` collapsée en `90` → **issue #791** (sans PR) — MEDIUM

`cinesort/app/omdb_cross_check.py:124` — `int(min_confidence_for_call or 90)` : un seuil `0`
(= « toujours appeler OMDb ») est falsy et bascule sur le défaut `90`, l'**inverse** de l'intention.
Confusion sentinelle 0/None/absent. **Pas de PR** : il faut d'abord confirmer la sémantique voulue de
`0` (garde `is None` explicite vs clamp) avant de trancher.

### A5 — Plan TV : `warning_flags` jamais peuplés → **issue #792** (sans PR) — MEDIUM

`cinesort/app/plan_support_replan.py:995` — `_plan_item` (l.771-773) enrichit `warning_flags` avec
subtitle/integrity/not_a_movie/year_missing, mais `_plan_tv_episode` initialise `warning_flags=[]`
sans jamais les calculer. **Asymétrie** : les épisodes TV n'exposent jamais ces avertissements, même
sur fichier tronqué/mal identifié. **Pas de PR** : la parité complète demande de décider quels checks
s'appliquent légitimement au TV (factorisation non triviale).

  « manque `imax`/`unrated` ». C'est un **design intentionnel**, prouvé par le test existant
  `test_imax_not_extended_excluded_at_high_delta`. Aucune issue créée (aurait été un faux positif).
- **Filtre 8 (proportionnalité)** : les 4 PRs sont chacune < 60 LOC, avec tests neufs quand le
  symbole n'était pas couvert (`_check_ts`, `_write_cache`). Les 3 findings à arbitrage produit sont
  restés en issue plutôt que forcés en PR.
