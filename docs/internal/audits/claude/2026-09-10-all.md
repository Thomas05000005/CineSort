## Par module

### A1 — `cinesort/app/quarantine_ttl.py:938` (`start_quarantine_ttl_cron._worker`) — **severite 3**, categorie 19, persona RELIABILITY

`start_quarantine_ttl_cron` recoit son `ttl_days` d'`app.py:676` / `app.py:1180`, qui le lit **une seule fois,
au boot**. `_worker` le capture dans sa closure et le rejoue a chaque cycle de 24 h :

```python
_run_purge_once(api, days)          # `days` = valeur du DEMARRAGE
while not stop_event.is_set():
    if stop_event.wait(interval_s):
        return
    _run_purge_once(api, days)      # idem, 24 h plus tard, toute la session
```

Toute la chaine aval propage la valeur figee (`run_facade.purge_quarantine_bucket` ->
`_purge_quarantine_bucket_impl` -> `purge_review_bucket`). Et **aucun site du depot ne pose
`_quarantine_ttl_stop`** : le cron ne peut etre ni arrete ni redemarre.

**Ce que l'utilisateur voit.** Parametres > Quarantaine, hint « **0 = désactivé** », `min: 0`
(`parametres.js:363-364`), sans mention de redemarrage. Il saisit 0 ; la sauvegarde persiste bien l'entier 0
(`_save_section_advanced`, borne `[0, 3650]`). Puis, dans les 24 h, le cron purge `_review/` a 30 jours — des
**fichiers video**, sur le **seul chemin de suppression automatique du depot**.

**Ce qui rend le diagnostic univoque** : le meme cycle relit deja la cfg — donc le `root` — a chaque passage
(`cinesort_api._build_quarantine_cfg`, appele par `_purge_quarantine_bucket_impl`). L'intention « lire l'etat
courant a chaque cycle » etait presente dans la fonction ; elle s'arretait avant le TTL.

**Pourquoi personne ne l'a vu.** Deux batteries couvrent le sujet, chacune d'un cote du trou :

| Test | Ce qu'il prouve | Ce qui lui echappe |
|---|---|---|
| `test_zero_desactive_les_crons.py` | le zero PARVIENT a la garde — par analyse AST des deux chemins de **boot** (`main_api`, `_startup`) | le cycle suivant, ou le reglage n'est plus relu |
| `test_quarantaine_ttl_v77.py` | la garde `days <= 0` marche — il passe `ttl_days=0` **directement au demarreur** | que le zero y parvienne autrement qu'au boot |

C'est exactement la forme du defaut d'origine, un cran plus loin : une garde **correcte** et **inatteignable**.

**Correctif** (PR #1242) : un helper `_ttl_du_cycle(api, defaut)` relit `quarantaine_ttl_days` via
`api.settings.get_settings()` avant chaque cycle. Le repli est **la valeur du boot**, jamais une constante — un
reglage absent laisse le boot decider, et une valeur illisible ne doit surtout pas valoir 0, ce qui
DESACTIVERAIT une purge que l'utilisateur n'a pas desactivee. Semantique alignee sur `app.reglage_entier` : seul
le zero **explicite** est preserve.

L'appel est pose dans `_worker`, **pas** dans `_run_purge_once` : `trigger_now` garde son comportement exact et
les batteries existantes sont inchangees. Leurs doublures sont des `SimpleNamespace(run=...)` sans `.settings`,
donc l'`AttributeError` retombe sur le repli — verrouille par `LeRepliProtegeLExistantTests`.

### A2 — `cinesort/ui/api/cinesort_api.py:1097` (`_sync_watcher`) — **severite 2**, categorie 19, persona UX

Le commentaire du site d'appel dit « Toggle watcher **dynamique** » (`:989`). Il l'est pour `watch_enabled`
seulement :

```python
if want and (self._watcher is None or not self._watcher.is_alive()):
    ...
    interval_min = max(1, min(60, int(settings.get("watch_interval_minutes") or 5)))
    self._watcher = FolderWatcher(self, interval_s=interval_min * 60, roots=roots)
```

Quand le watcher **tourne deja**, la condition est fausse : ni `watch_interval_minutes` ni `roots` ne sont
relus. Changer l'intervalle de surveillance, ou **ajouter une racine de bibliotheque**, reste sans effet jusqu'a
un toggle off/on ou un redemarrage — et rien ne le dit a l'utilisateur.

Non destructif (le watcher declenche des scans, il ne supprime rien), d'ou la severite 2. **Pas de PR** : le
remede — reconstruire le watcher quand l'intervalle ou les racines changent — demande de decider ce qu'on fait
d'un cycle de surveillance en cours, ce qui est un arbitrage.

### A4 — `cinesort/app/quarantine_ttl.py:72` (`PURGE_PRESERVED_SUBDIRS`) — **severite 1**, categorie 10, persona DB

Son commentaire l'annonce comme la liste des sous-dossiers « explicitement PRESERVES par **TOUTES** les purges
(TTL + "Vider maintenant") ». Mesure : **un seul lecteur**, `list_review_bucket_files:429` — le compteur
`purge_scope_files_count`. Les deux purges reelles reecrivent le litteral :

```
quarantine_ttl.py:650   excluded = set(TTL_SUBDIRS) | {"_duplicates_user_decided"}   # purge_review_bucket
quarantine_ttl.py:746   excluded = set(TTL_SUBDIRS) | {"_duplicates_user_decided"}   # purge_review_bucket_all
```

**Aucun defaut observable aujourd'hui** : l'ensemble a un seul element, identique au litteral. Le risque est
latent et precis — ajouter un preserve a la constante ferait que le compteur l'exclut du perimetre annonce a
l'utilisateur pendant que les purges le supprimeraient. C'est exactement le defaut « FIX #8 » que ce meme
commentaire dit avoir corrige, reintroduit par l'autre porte.

**Pas de PR** : le correctif (`| PURGE_PRESERVED_SUBDIRS` aux deux sites) est strictement equivalent
aujourd'hui, donc **aucun test ne peut etre vu ROUGE sans lui**. Le depot exige cette preuve ; un test AST sur
le code source serait par ailleurs de la famille proscrite par les conventions.

### A5 — `cinesort/domain/conversions.py:156` (`to_optional_bitrate`) — **severite 1**, categorie 2, persona PERFORMANCE

La docstring promet « Accepte les unites usuelles : Gb/s, Mb/s, Kb/s (**binaire et decimal**) ». Le motif
`_BITRATE_UNIT_RE` reconnait bien les trois formes binaires (`gib/s`, `mib/s`, `kib/s`), mais la conversion les
traite comme decimales :

```python
if unit.startswith("gb") or unit.startswith("gi"):
    return to_optional_int(base * 1_000_000_000)      # gibibit = 2**30, soit +7,4 %
```

Ecart : 7,4 % (Gi), 4,9 % (Mi), 2,4 % (Ki). **Effet non mesure** : aucune source de sonde connue du depot
n'emet de suffixe binaire pour un debit (MediaInfo rend « 25.0 Mb/s »), donc le chemin est probablement inerte.
Signale comme incoherence entre le contrat ecrit et le code, pas comme defaut de comportement — la severite le
reflete.
