## A1 — le titre qui n'existe plus (severite 3, corrige par #1278)

### Le mecanisme

`title_helpers.NOISE_RE` retire ses ~70 jetons techniques **INCONDITIONNELLEMENT**,
donc aussi a l'interieur du titre. Quand le titre **est** fait de ces jetons, la
normalisation rend la chaine vide :

```
_norm_for_tokens("Opus")     -> ""
_norm_for_tokens("Hybrid")   -> ""
_norm_for_tokens("Limited")  -> ""
_norm_for_tokens("Proper")   -> ""
_norm_for_tokens("Stereo")   -> ""
```

Et le vide degenere ses lecteurs :

| Lecteur | Sur « Opus » |
|---|---|
| `_title_similarity("Opus", "Opus")` | **0.00** — un titre contre LUI-MEME |
| `_tmdb_prefix_equivalent` | `False` (garde `if not nq or not nc`) |
| `movie_key("Opus", 2025)` | `"\|2025"` |

Le premier est decisif. `core.build_candidates_from_tmdb:1432` :

```python
if sim < _TMDB_STRICT_MIN_SIM and not (year_is_close and sim >= 0.35):
    continue
```

`_TMDB_STRICT_MIN_SIM` vaut 0,50 ; la seule porte de sortie exige `sim >= 0.35`.
Avec `sim = 0.00`, **le candidat que TMDb rend en tete est jete**. Deroule complet,
lu ligne par ligne :

```
dossier « Opus (2025) »
  clean_title_guess          -> "Opus"                (correct, scene_parser fait son travail)
  tokens("Opus")             -> []                    -> token_count = 0  -> min_sim = 0.46
  _norm_for_tokens("Opus")   -> ""                    -> is_short_title   -> min_sim = 0.90
  _title_similarity(exact)   -> 0.00
  seuil absolu 0,50          -> continue
  => out = []   (aucun candidat TMDb, pour un film que TMDb rend exactement)
```

Le film reste non identifie **a chaque scan, definitivement** : pas de titre
propre, pas de jaquette, pas de collection, jamais auto-approuve. Aucun
rattrapage : `_rescore_with_alternative_titles` rejoue la MEME fonction, et le
candidat n'existe deja plus.

### Pourquoi une TRONCATURE, elle, est inoffensive

C'est la distinction qui fait le correctif. `NOISE_RE` tronque aussi des titres,
et cela ne nuit pas — parce que la troncature est **SYMETRIQUE** :

```
"Internal Affairs" (dossier)      -> "affairs"
"Internal Affairs" (candidat TMDb) -> "affairs"
-> cov = 1.00, seq = 1.00 : le verdict est JUSTE
```

La chaine vide, elle, ne se compare a rien.

### Le depot avait deja tranche — a l'AUTRE site

Il existe **deux** tables de tags techniques dans `domain/`, et elles portent les
memes jetons ambigus :

| Table | Role | Garde « mots ambigus » |
|---|---|---|
| `scene_parser._NOISE_RE` | EXTRAIRE le titre | **OUI**, position-aware + test dedie |
| `title_helpers.NOISE_RE` | COMPARER le titre | **NON** |

Le test qui verrouille la premiere nomme les films :

> `tests/test_scene_parser_title_mutilation_v77.py::MotsAmbigusDeLaListeINCONDITIONNELLETests`
> « `_NOISE_RE` retirait des mots qui sont de vrais titres de films. [...]
> `Cam (2018) -> ''` le titre ENTIER disparaissait ; `Opus (2025) -> ''` idem »
> `TITRES_REELS` : Opus (2025), Hybrid (2007), Limited (2019), Proper (2022),
> Internal Affairs (1990), Complete Unknown (2016)

Le correctif a ete pose la, pas ici. Signature « une garde acquise et ses sites
oublies » — la meme que #1209, #1210 et #1220.

Le detail s'etend au-dela des mots : `title_helpers.NOISE_RE` porte
`5\.?1`, `7\.?1`, `2\.?0` **avec le point optionnel**, donc elle matche `51`,
`71`, `20` nus. C'est exactement la cause (a) que `scene_parser` a corrigee en
juin 2026 en rendant le separateur OBLIGATOIRE :

> « `[\s.]?` rendait le separateur de canal OPTIONNEL -> "21"/"50"/"71"/"20"
> matchaient comme si c'etait du 2.1/5.0/7.1/2.0 [...] "71 (2014)" -> "2014" »

### Le remede, et son argument de surete

```python

if normalise:
    return normalise
return _reduire_aux_tokens(s)   # NOISE_RE a tout absorbe : le titre EST ses jetons
```

Il **n'arbitre rien** — retirer `opus` / `limited` / `proper` de la table

**Monotone par construction** : le comportement ne change QUE la ou le resultat
actuel est `""`. Et la, tout lecteur etait deja degenere — `core.
_candidate_consensus_bonus` porte d'ailleurs deja un `if not title_key:
return 0.0` : **la meme famille, traitee a un seul site**.

## L'enseignement de methode du jour

**Deux tables qui portent les memes jetons ne partagent pas leurs gardes.**

`scene_parser._NOISE_RE` et `title_helpers.NOISE_RE` listent les memes mots
ambigus, a quelques entrees pres. La premiere a recu un garde position-aware, un
test dedie de 60 lignes, et une docstring qui nomme les films concernes. La
seconde n'a rien recu — et c'est elle qui decide si un film est identifie.

Le depot a une regle contre ca (« SOURCE UNIQUE », appliquee aux tags providers
le 2026-08-31, #9), mais elle n'a jamais ete appliquee aux tables de BRUIT :
elles ont des roles differents (extraire vs comparer), donc leur fusion est un
arbitrage, pas une evidence.

> Quand on corrige une table, chercher ses **jumelles par le contenu**, pas par
> le nom : `grep -l "1080p" cinesort/domain/*.py` les designe en une seconde.

Corollaire, paye dans le meme mouvement : **la chaine vide n'est pas une
troncature de plus.** Une normalisation qui tronque reste juste par symetrie ;
une normalisation qui vide fait mentir tous ses lecteurs a la fois. C'est le meme
enseignement que `.get(cle, 0)` — « inconnu » n'est pas « pire » — transpose du
domaine des rangs a celui des chaines.
