### A1 — `estimate_apply_size` compte les rows au `row_id` vide (#698, PR #703)

`disk_space_check.py:75` : `if rid and rid not in approved_keys: continue`. Le garde `rid and` faisait qu'une row **sans** `row_id` n'etait jamais exclue → sa taille etait ajoutee a l'estimation meme non approuvee, gonflant `needed_bytes` et pouvant declencher un faux « Espace disque insuffisant ». Fix : `if rid not in approved_keys: continue` (une row au row_id vide ne peut jamais etre dans `approved_keys`, indexe par row_id). Test `test_size_empty_row_id_not_counted` ajoute. 9/9 verts.

### A2 — `_build_pseudo_probe` ne renseigne jamais `video.width` (#699, issue-only)

`run_flow_support.py` (~L1400) : `_build_pseudo_probe` omet `video["width"]`, donc `_quality_info_for_row` (~L1470) `if w and h: info["resolution"] = ...` ne se declenche jamais → la ligne « Resolution » des cartes de doublons A/B reste vide (fix « R8-059 » partiellement mort). Fix identifie (ajout `width` + fallback `elif h`), **non pousse** : `run_flow_support` importe transitivement `cinesort.domain._fuzzy_normalize`, module **absent** (BLOCKER preexistant #646, PR #647 non mergee) — impossible de faire tourner `test_comparator_display_v77.py` localement. Commentaire poste sur #699 documentant le fix pret + le blocage.

### A3 — `get_history_stats` lit `decision` sur des `PlanRow` sans ce champ (#700, issue-only)

`history_support.py:347` : `"decision": str(pr.get("decision") or "").strip().lower()`. `pr` provient de `asdict(PlanRow)` ; or `PlanRow` (core.py:392-432) **n'a pas** de champ `decision` (les decisions vivent dans `validation.json`/`film_decisions_v2`). Resultat : `decision` toujours vide → statut historique constamment « Approuve » (fix « R8-062 » no-op). Laisse en issue-only : le fix correct exige de brancher la vraie source de decision, choix de conception a valider (hors niveau modere).

### A4 — `wal_growth_kb` mesure apres `wal_checkpoint(TRUNCATE)` (#701, PR #704)

`nas_validation.py:284` capturait `wal_after` **apres** le `finally` qui execute `PRAGMA wal_checkpoint(TRUNCATE)` (L275), remettant le WAL a ~0 → `wal_growth_kb` toujours ~0, metrique de diagnostic NAS morte. Fix : capture du pic juste apres la boucle de lectures, avant le TRUNCATE ; defaut `wal_after = wal_before`. Test `test_wal_growth_measured_before_truncate` (force `journal_mode=WAL`, assert `> 0`). 14/14 verts.

### A5 — `_looks_like_nested_extra_video` code mort (#702, PR #705)

`scan_helpers.py:154-159` : fonction jamais appelee (seule autre occurrence = mention docstring L225). Logique deja dupliquee inline dans la closure `_file_looks_bonus` et exposee publiquement par `file_name_looks_bonus`. Suppression + reformulation docstring. Couverture inchangee (25/25 tests scan-domain verts).
