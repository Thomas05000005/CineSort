## Par module

### cinesort/ui/api/demo_support.py:303 — RETENU (Issue #801, PR #802)

- `_build_quality_metrics(film)` emettait un schema `metrics["video"]/["audio"]`
  obsolete. Le consommateur reel `_build_library_rows`
  (`library_support.py:310-484`) lit **exclusivement** `metrics["detected"]`
  (`width`/`height`/`video_codec`/`duration_s`/`languages`/`audio_best_codec`)
  + `metrics["probe_quality"]`.
- Consequence : les 15 films du mode demo s'affichaient codec `unknown`,
  resolution degradee, `duration_s=0`, `audio_languages` vide,
  `probe_quality=UNKNOWN` -> vue Bibliotheque demo cassee.
- **Cause d'invisibilite** : `test_demo_mode.py` ne verifiait que la presence de
  15 `quality_reports` en DB, jamais le rendu Bibliotheque.
- **Fix** : reecriture de `_build_quality_metrics` vers le schema `detected`
  (ref `quality_score.py:1622`), + `_RESOLUTION_WH`, duree/bitrate/taille
  derives de facon deterministe. 2 tests de contrat ajoutes
  (`test_quality_metrics_uses_detected_schema`,
  `test_quality_metrics_covers_all_demo_films`).
- **Severite** : BUG (3) · **Confiance** : 0.90 · **Action** : PR #802 (Closes #801).

### cinesort/ui/api/library_timeline_support.py:277 — CASCADE #730 (enrichissement CAS B)

- `rows = _build_library_rows(api, run_id)` (ligne 238) -> `row["path"]` est
  **toujours** vide (meme root que #730 : `source_path`/`mtime` absents de
  `PlanRow`).
- Ligne 277-278 : le fallback `_file_mtime_to_month(path)` recoit `""` ->
  retourne `None` -> le fallback filesystem est **integralement mort**
  (`using_filesystem` ligne 279 jamais vrai, `source` jamais `filesystem`/`mixed`
  malgre la docstring lignes 10-11).
- Le chemin Jellyfin (`row.get("tmdb_id")`) fonctionne, lui, car
  `_build_library_rows` expose un `tmdb_id` resolu (`library_support.py:434`).
- **Severite** : QUALITY/BUG (2) · **Confiance** : 0.90 · **Action** :
  commente sur #730 (le fix propose la, `path` derive de `Path(folder)/video`,
  resout les 3 consommateurs d'un coup). Pas d'issue en double.

### cinesort/ui/api/apply_support.py:1584 — RAPPORT SEUL

- `_r.tmdb_id = int(_ov["tmdb_id"])` : `PlanRow` (`core.py:377-427`, `@dataclass`
  sans slots) n'a **aucun** champ `tmdb_id`. L'affectation cree un attribut
  dynamique jamais relu (grep `.tmdb_id` dans apply_core/apply_support : 0
  lecture au niveau row). `serialize_rows_for_payload=asdict()` ne serialise que
  les champs declares -> l'override tmdb_id est silencieusement perdu.
- Les overrides `proposed_title`/`proposed_year` (memes lignes) fonctionnent car
  ce sont de vrais champs. Aucun impact visible utilisateur (l'apply utilise
  titre/annee, pas le tmdb_id au niveau row).
- **Severite** : STYLE (1) · **Confiance** : 0.90 · **Action** : rapport seul
  (proportionnalite — 227 issues existantes, aucun impact runtime).

### cinesort/app/export_support.py:104 — RAPPORT SEUL

- `total = sum(tiers.values()) or 1` : si le dict `quality_tiers` portait
  simultanement les clefs modernes (platinum/gold/...) ET legacy
  (premium/bon/...) pendant une migration, le denominateur serait double-compte
  -> pourcentages sous-evalues. La boucle sous-jacente lit `EITHER` moderne
  `OR` legacy par tier (ligne 112) mais `total` somme tout.
- **Severite** : STYLE (1) · **Confiance** : 0.55 (edge migration-only, dict
  probablement mono-schema en pratique) · **Action** : rapport seul.
