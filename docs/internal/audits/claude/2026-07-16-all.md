## Par module

### cinesort/infra/plex_client.py (Issue #753 -> PR #756)

- `_get()` appelle `resp.json()` sans borner la taille du body apres
  `raise_for_status()`. **Seul client REST** dans ce cas : jellyfin / radarr / tmdb /
  omdb ont tous la garde 10 Mo.
- Un serveur Plex usurpe (on-path) ou une tres grosse bibliotheque peut forcer le parse
  JSON d'un body non borne dans le thread scan -> OOM.
- **Severite** : BUG (2) — **CWE-400** Uncontrolled Resource Consumption
- **Fix** : borne `len(resp.content) > 10_000_000 -> PlexError`, alignee sur les clients
  freres. `PlexError` se propage (pas capturee par les `except requests.*`).
- Test ajoute : `PlexBodySizeGuardTests` (mock `_session.get`).

### cinesort/domain/naming.py:296 (Issue #754 -> PR #758)

- `build_naming_context` prenait `audio_tracks[0]` (ordre du conteneur) pour
  `{audio_codec}` et `{channels}`.
- Sur un fichier ou une piste lossy compatible precede la vraie meilleure piste
  (TrueHD/Atmos), le nom genere affiche le codec **inferieur**.
- Diverge de `quality_score._best_audio_track` (R8-039) et `duplicate_compare._best_audio`.
- **Severite** : BUG (2), **needs-review** (impact naming, memoire user INVIOLABLE #1
  sur titres respectee : seuls les placeholders codec/canaux changent, pas le titre).
- **Fix** : helper `_best_audio_track` self-contained (rang codec > canaux > bitrate via
  `AUDIO_CODEC_RANK`, module feuille deja importe -> aucun cycle).

### cinesort/domain/audio_analysis.py:30-46 (Issue #755 -> PR #757)

- Le frozenset `_COMPAT_PAIRS` et le bloc `if len(codecs) == 2: if pair in _COMPAT_PAIRS`
  dans `_find_duplicate_tracks` sont **du code mort** : l'emission d'un doublon exige
  `count >= 2` du MEME codec. Deux codecs differents donnent `counts={a:1, b:1}` et ne
  sont jamais signales -> l'exemption ne change jamais le resultat.
- Verifie : aucun test ne depend de `_COMPAT_PAIRS` (grep tests/ vide).
- **Severite** : STYLE (1) — code mort
- **Fix** : suppression du frozenset + bloc, commentaire expliquant l'invariant.

### cinesort/domain/perceptual/audio_perceptual.py:586 (Issue #752, sans PR)

- `classify_drc` renvoie `"broadcast_compressed"` @0.85 alors qu'**une seule** metrique
  DRC est presente (confusion score `0` = absent vs mesure a `0`).
- **Severite** : BUG (2), **confidence 0.75 -> needs-review** : c'est un changement de
  calibration/seuil perceptuel, pas un fix mecanique. Laisse en **issue seule** (pas de
  PR auto) — arbitrage calibration reserve, cf categorie 17.
