## Par module

### `cinesort/ui/api/library_support.py`
- **`_build_library_rows()` lignes 138-148** — severity **2 (QUALITY)** —
  Deux blocs `try/except` silencieux pour `list_perceptual_reports()` et
  `list_quality_reports()` retournent `[]` sur OSError/AttributeError/
  TypeError/ValueError sans aucun logger. En cas d'erreur DB (corruption,
  schema migration ratee, fichier locke par AV), la library est silencieusement
  vide, l'utilisateur ne voit rien et le debug est impossible.
  - **Fix** : ajouter `logger.warning("...: %s", exc)` avant chaque `... = []`,
    en suivant le pattern deja utilise ligne 134 (`logger.warning("library_support cannot get store: %s", exc)`).
  - **Effort** : trivial (~6 LOC, ~5 min).
  - Confidence : 0.88.
  - Fingerprint : `fd7dff37`

### `cinesort/ui/api/perceptual_support.py`
- **`_validate_and_load_context()` ligne 146** — severity **2 (QUALITY)** —
  Le cache hit retourne `{"ok": True, "cache_hit": True, "perceptual": existing.get("metrics", {})}`
  mais les champs orphan exposes apres issue #32 (`audio_fingerprint`, `ssim_self_ref`,
  `upscale_verdict`, `spectral_cutoff_hz`, `lossy_verdict`) sont stockes au
  top-level du report perceptual (cf lignes 446-450 dans le meme fichier), pas
  dans `metrics`. La premiere execution les retourne, le cache hit non.
  - **Fix** : retourner aussi les top-level fields : `{... "perceptual": {**existing.get("metrics", {}), "audio_fingerprint": existing.get("audio_fingerprint"), "spectral_cutoff_hz": existing.get("spectral_cutoff_hz"), "lossy_verdict": existing.get("lossy_verdict"), "ssim_self_ref": existing.get("ssim_self_ref"), "upscale_verdict": existing.get("upscale_verdict")}}`
  - Ou refactor : centraliser la construction du payload "perceptual" pour les 2 paths
    (cache hit + execution fraiche).
  - **Effort** : small (~10 LOC + 1 test).
  - Confidence : 0.80 (borderline — issue plutot que PR pour validation owner).
  - Fingerprint : `e4cb186a`
