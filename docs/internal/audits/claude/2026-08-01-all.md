## Detail du finding retenu (S324)

Les 5 appels `hashlib.sha1()` de la couche `app/` sont des **empreintes de
contenu** (cache / dedup incremental), jamais des hachages de securite :

- `apply_core.py:284` (`sha1_quick`) — empreinte fichier pour dedup/conflits apply
- `plan_support_core.py:271` (`cfg_signature_for_incremental`) — cle de cache config
- `plan_support_core.py:418` (`_nfo_signature`) — cache signature NFO
- `plan_support_core.py:445` (`folder_signature`, fallback scandir)
- `plan_support_core.py:478` (`folder_signature`) — signature dossier

Sans `usedforsecurity=False` : remontes par bandit (B324, `.github/workflows/bandit.yml`,
non skippe) dans l'onglet Security, et **exception en mode FIPS**. Le fix aligne sur
le pattern deja etabli (`film_identity.py:55`, `poster_proxy.py:66/545`,
`quality_simulator_support.py:150` pour md5). Kwarg additif, **zero changement de
comportement**.

Le bug **logique** distinct de `folder_signature` (`sha1(b"")` -> collision de cache
sur erreur scandir) reste suivi separement par **#696**.
