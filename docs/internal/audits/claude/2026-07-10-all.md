## Résumé exécutif

Six findings retenus après filtrage, tous corrigés en PR isolées (une par finding, branche fraîche depuis `main`). Deux sont de sévérité sécurité élevée : **A5** (contournement SSRF du endpoint metadata cloud via IPv6 IPv4-mapped — BLOCKER, CWE-918) et **A4** (corruption du cache TMDb par écritures concurrentes — CWE-362). **A6** borne l'extraction d'archives ffmpeg contre les zip bombs (CWE-409). Côté fiabilité, **A3** supprime un échec silencieux de la purge incrémentale sur grosses racines (« too many SQL variables »). **A1** ressuscite le simulateur de qualité (attribut `api._store` inexistant → feature morte) et **A2** corrige des champs de payload dérivés d'attributs absents de `PlanRow`.

Aucun correctif ne touche l'architecture verrouillée (import-linter), les couleurs de tiers, le stockage des tokens DPAPI, ni les titres de films. Toutes les PRs respectent le principe de rétro-compatibilité.

## Findings par catégorie

### A5 — SSRF IPv4-mapped (sécurité, BLOCKER, CWE-918) — #733 / #735
`cinesort/infra/network_utils.py`. La validation d'hôte ne rejetait que la forme IPv4 des adresses link-local. Un hôte `[::ffff:169.254.169.254]` (IPv4-mapped IPv6) contournait le filtre et atteignait le endpoint metadata cloud. Correctif : déplier `ipv4_mapped` avant `is_link_local`. Tests ajoutés : `test_ipv4_mapped_metadata_blocked`, `test_ipv6_link_local_blocked`.

### A4 — Race cache TMDb (sécurité, BUG, CWE-362) — #732 / #736
`cinesort/infra/tmdb_client.py` (2 sites). Le `.tmp` d'écriture atomique portait un suffixe fixe : deux writers concurrents au boot corrompaient le cache par rename croisé. Correctif : suffixe unique `.tmp.{pid}.{time_ns}` + cleanup best-effort (`contextlib.suppress(OSError)`).

### A6 — Zip bomb ffmpeg (sécurité, BUG, CWE-409) — #734 / #739
`cinesort/infra/probe/auto_install.py` (3 sites). `zf.read(entry)` chargeait chaque entrée entière en mémoire sans borne. Correctif : plafond `_MAX_UNCOMPRESSED_BYTES = 300 MiB` vérifié via `getinfo().file_size`, extraction en flux (`shutil.copyfileobj`, buffer 1 MiB). Test : `test_rejects_oversized_entry`.

### A3 — Purge incrémentale non bornée (mainteneur, BUG) — #731 / #740
`cinesort/infra/db/repositories/scan.py`. Les deux `prune_*` construisaient un `DELETE ... NOT IN (?,?,…)` avec un placeholder par entrée conservée ; au-delà de `SQLITE_MAX_VARIABLE_NUMBER` (999 sur SQLite <3.32) la purge échouait silencieusement. Réécrit en SELECT des existants + calcul du stale en Python + `DELETE ... IN (chunk)` par lots de 500. Except élargis dans `plan_support_core.py`. Tests : `PruneIncrementalCacheBoundsTests` (1200 entrées).

### A1 — Simulateur qualité mort (mainteneur, BUG) — #729 / #738
`cinesort/ui/api/quality_simulator_support.py`. Les deux fonctions lisaient `api._store`, attribut jamais défini → aucun rapport chargé. Correctif : helper `_get_store()` résolvant le store via `api._get_or_create_infra(api._get_state_dir())`, run id via `store.run.get_latest_run()`. Tests réalignés sur `_get_or_create_infra.return_value`.

### A2 — path/added_ts dérivés d'attributs absents (mainteneur, QUALITY) — #730 / #737
`cinesort/ui/api/library_support.py`. Le payload lisait `source_path`/`mtime`/`size_bytes`, absents de `PlanRow`. Correctif : `path` dérivé de `Path(folder)/video` ; `added_ts=0.0` documenté et déféré à #730 (`PlanRow` ne porte pas de timestamp — traitement séparé requis). PR en `Refs #730`, pas `Closes`.
